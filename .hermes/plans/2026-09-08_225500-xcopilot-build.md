# X-Copilot Build Plan

## Goal
Build a self-growing AI agent for Windows (X-Copilot) from the specification in `X-Copilot.md` — a Python 3.11 + Node.js CLI tool with 5-layer memory, auto skill creation, permission pipeline, and Windows-native installer.

## Current Context / Assumptions
- **Workspace**: `/c/Users/tnvma/Projects/X-Copilot/` (empty, newly created)
- **Spec source**: `/c/Users/tnvma/AppData/Local/hermes/attachments/X-Copilot.md` (901 lines, full architecture)
- **Target platform**: Windows 10 19041+ / Windows 11, PowerShell 5.1+, Python 3.11, Node.js 18+
- **Runtime**: Python 3.11 (core engine), Node.js (CLI tooling)
- **Memory**: SQLite + JSONL (episodic), ChromaDB (semantic/vector), SKILL.md files (procedural)
- **No external deps**: No WSL, Docker, Cygwin — only winget, PowerShell, built-in Windows tools
- **Installer**: One-command PowerShell (`irm https://xcopilot.ai/install.ps1 | iex`)

## Architecture / Proposed Approach
Two-process architecture: **Python core** (agent loop, memory, learner, skills, permissions) + **Node.js CLI** (user-facing `xcopilot` command, installer, plugin loader). Communication via stdio JSON-RPC. The Python package installs via `pip install x-copilot`; the Node CLI wraps it and provides the `xcopilot` command. Skills are portable `SKILL.md` files with YAML frontmatter, discoverable in `~/.xcopilot/skills/` (global) and `.xcopilot/skills/` (project). Memory layers persist to `~/.xcopilot/memory/`.

**Episodic schema** (SQLite):
```sql
CREATE TABLE events (
  id INTEGER PRIMARY KEY,
  timestamp TEXT NOT NULL,      -- ISO8601
  type TEXT NOT NULL,           -- tool_call, edit, accept, reject, error
  payload TEXT NOT NULL,        -- JSON
  project TEXT,                 -- project root path
  session_id TEXT NOT NULL
);
CREATE INDEX idx_events_project_time ON events(project, timestamp);
```

**ChromaDB collection**: `xcopilot_semantic` with metadata `{project, type, timestamp}`.

### Phase 2: Learner Engine (30 min)
File: `src/xcopilot/core/learner.py`

| Task | Method | Behavior |
|------|--------|----------|
| 2.1 Signal capture | `observe(signal: Signal)` | Accepts `Signal(type, payload, context)` from runtime |

**Signal types** (enum): `TOOL_CALL`, `TOOL_RESULT`, `USER_EDIT`, `USER_ACCEPT`, `USER_REJECT`, `ERROR`, `CORRECTION`.

**Pattern** (Pydantic model):
```python
class Pattern(BaseModel):
    id: str
    type: Literal["preference", "mistake", "pattern", "workflow"]
    description: str
    evidence: list[Signal]  # supporting signals
    confidence: float       # 0.0-1.0
    created_at: datetime
    last_reinforced: datetime
    applications: int = 0
```

## Risks, Tradeoffs, Open Questions

| Risk | Mitigation |
|------|------------|
| ChromaDB requires native deps on Windows | Bundle wheels, fallback to SQLite-vec if install fails |
| PowerShell installer needs HTTPS cert trust | Use `irm` with `-UseBasicParsing`, fallback to manual |
| Skill marketplace rate limits (GitHub API) | Cache responses, use authenticated requests with token |
| Checkpoint storage growth | Auto-prune checkpoints older than 30 days, max 1000 per session |
| Python ↔ Node IPC latency | Keep hot path in Python; Node only for CLI parsing and plugin sandbox |
| Windows Defender false positives on installer | Sign installer, submit to Microsoft for reputation |

**Open questions**:
1. **Model provider default**: Spec says DeepSeek V4 Flash — need API key handling in config
2. **Graph DB choice**: NetworkX in-memory vs persistent (SQLite/Neo4j) — start with NetworkX + periodic disk dump
3. **Plugin sandbox**: `vm2` is deprecated — use `isolated-vm` or `node:vm` with strict context
4. **Self-update on Windows**: Replacing running executable requires restart — use `MoveFileEx` with `MOVEFILE_DELAY_UNTIL_REBOOT` or staged update
